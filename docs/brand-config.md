# 品牌白名单配置说明

换品牌 / 换品类只用改 `config/brand.json`，不需要动代码。

```bash
cp config/brand.example-generic.json config/brand.json   # 小牛的完整示例
```

或者用环境变量指向任意配置文件：

```bash
XIANYU_BRAND_CONFIG=/path/to/my-brand.json node scripts/xianyu.js scan --hours 6
```

---

## 字段总览

| 字段 | 作用 | 命中后 |
|---|---|---|
| `brandPatterns` | 品牌名写法 | **收**（前提：不是配件、不是仿冒） |
| `modelPatterns` | 型号词（标题不写品牌名时兜底） | **收**（同上） |
| `accessoryStrong` | 明确自报是配件的词 | **剔** |
| `accessoryPart` | 单件配件词 | **剔**（仅当无车辆主体特征时） |
| `vehicleSignals` | 车辆主体特征 | 保护：有它就不算单件配件 |
| `fakePatterns` | 仿冒 / 山寨 | **剔** |
| `otherBrands` | 其他品牌（**仅用于排障提示**） | 不参与判定 |
| `generations` | 代际判定规则（可选） | 供 `mmax.js` 这类脚本用 |

每个字段都是**正则字符串数组**，会被 `|` 拼成一个大的正则，大小写不敏感。

---

## 五个字段怎么填

### `brandPatterns` — 品牌名

把目标品牌的所有写法都列出来。中文名、英文名、常见简写、防屏蔽写法。

```json
["九号", "ninebot", "nine\\s*bot", "(?<![\\d])9\\s*号"]
```

注意 `(?<![\\d])9\\s*号` 这个负向后视 —— 避免把「19号」「29号」这种地址/编号当成品牌。

### `modelPatterns` — 型号词

标题经常不写品牌名（「MMAX110 空车 不带电池」）。靠型号词兜底。

```json
["mmax", "机械师", "mz\\s*130", "f90", "m95c"]
```

⚠️ 型号词要选**高辨识度**的。`F90` 可以用，`110` 不行 —— 后者会和价格、尺寸混淆。

### `accessoryStrong` — 自报配件

卖家自己说是配件的，直接剔。

```json
["适用", "适用于", "同款", "兼容", "代拍", "代购", "零配件", "配件出售"]
```

### `accessoryPart` — 单件配件

这些词出现时**不一定**是配件贴 —— 可能是整车在描述赠品。所以要和 `vehicleSignals` 配合：

```
有配件词 + 无车辆主体特征 = 配件贴 → 剔
有配件词 + 有车辆主体特征 = 整车   → 收
```

```json
["电池组", "充电器", "头盔", "后视镜", "座套", "手机支架", "挡泥板", "刹车片"]
```

### `vehicleSignals` — 车辆主体特征

这是**保护性字段**，不是过滤字段。作用是把「整车配件齐全」从配件贴里救回来。

```json
["公里", "km", "空车", "过户", "上牌", "车牌", "成色", "车况",
 "准新", "激活", "里程", "整车", "自提", "手续", "合格证", "钥匙"]
```

**填得越全，误杀越少。** 实测把这一栏从 8 个词补到 34 个词，误杀从 20% 降到 0。

### `fakePatterns` — 仿冒

```json
["假九号", "仿九号", "高仿", "精仿", "山寨", "贴牌车", "杂牌", "nicebike"]
```

二手市场里「假9号」「仿九号」是明确自报的，看到就剔。

## 一个反直觉的字段：`otherBrands`

它**不参与判定**。

很多人第一反应是"排除其他品牌" —— 这是错的。卖家写「支持换雅迪」「比小牛好骑」「吊打台铃」时，
那台车是**目标品牌的车**。按黑名单来写，实测误杀率 20%。

这个字段的唯一用途是**排障提示**：当一条商品没命中任何规则时，`judge()` 会告诉你
「其他品牌」还是「无品牌特征」，方便你调规则。

```js
judge('雅迪冠能 5000公里')
// { ok: false, other: true, reason: '其他品牌' }
//                    ↑ 只是提示，不是判定依据
```

---

## `generations` — 代际判定（可选）

有些产品线在二手市场一个名字指好几代车，价格差 2000–3000。这时需要按优先级拆分。

```json
"generations": {
  "MMAX110 MK2": ["mk\\s*2"],
  "MMax2 二代": ["机械师\\s*二代", "mmax2"],
  "MMAX110P": ["110\\s*p\\b"],
  "MMAX110": ["max\\s*110"],
  "MMAX90": ["max\\s*90"]
}
```

**数组顺序 = 优先级，顺序不能打乱。** `mk2` 必须先判，否则「机械师一代mk2」会被判成「机械师」基础款。

不需要这个功能的品类，直接写 `"generations": null`。

## 验证配置

改完配置跑一下测试：

```bash
node test/brand.test.js
```

测试用例是按**九号预设**写的。换品牌后这些用例会失败 —— 这是预期的，
请把你的品牌用例替换进去。core 的判定逻辑（配件/整车/仿冒）不需要改。

也可以单条调试：

```bash
node -e "
const { judge } = require('./scripts/lib-brand');
console.log(judge('小牛NQi 5000公里 带牌'));
"
```

输出会告诉你这条为什么被收 / 被剔：

```
{ ok: true, brand: true, model: true, vehicleSignal: true,
  accessory: false, fake: false, other: false, reason: '品牌名命中' }
```

## 这套逻辑的适用范围

不限于电动车。只要目标品类有这三个特征，白名单就比关键词搜索准得多：

1. **型号名混乱** —— 同一个名字指好几代产品
2. **配件噪音大** —— 卖整机的和卖零件的混在一起
3. **仿冒品存在** —— 有「适用XX」「兼容XX」这种擦边写法

比如：相机镜头、游戏机、显卡、乐器、健身器材。
